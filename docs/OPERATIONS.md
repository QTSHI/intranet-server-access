# 日常运维与排障

先区分故障发生在哪一层：网页 HTTPS、网页到应用、VPS 反向转发、内网设备到目标服务器、个人账户认证。每次只改变一层，并保留原配置和恢复步骤。

## 常用检查

以下名称与路径对应部署文档中的示例：

```sh
systemctl status intranet-server-access.service
journalctl -u intranet-server-access.service --since '10 minutes ago'
ss -ltnp 'sport = :8090'
ss -ltnp 'sport = :22002'
curl -fsS http://127.0.0.1:8090/api/session
curl -fsS https://lab.example.com/api/session
nginx -t
```

应用日志保留运行状态及聚合性能信息，不记录成员密码、终端正文或文件正文。对外分享日志前仍应检查是否带有部署地址、个人用户名或其他运维信息。

## 按现象排查

| 现象 | 优先检查 |
| --- | --- |
| 域名打不开或证书异常 | DNS 是否指向 VPS；80/443 可达性；证书路径、有效期和 Nginx 状态 |
| 页面返回 502 | 应用服务是否运行；`127.0.0.1:8090` 是否监听；Nginx upstream 是否一致 |
| 页面可见，但连接立刻失败 | WebSocket Upgrade 配置、真实网页 Origin 与 `LAB_ALLOWED_ORIGINS` 是否完全一致 |
| 提示校园连接暂不可用 | VPS 的反向监听是否存在；内网设备上的 SSH 进程是否退出；该设备能否访问目标服务器 |
| 主机身份核验失败 | 隧道实际目标是否正确；目标 SSH 主机密钥是否发生了经确认的合法变更 |
| 个人密码认证失败 | 目标账户、密码及密码认证方式；账户是否被锁定、到期或要求改密/额外验证 |
| 多次失败后暂时无法重试 | 按 IP 或用户名的认证限流；等待窗口恢复，再使用已确认正确的账户 |
| 终端正常，文件树不可用 | 该目标账户是否允许 SFTP；SFTP 子系统和个人主目录权限 |
| 文件可以读但不能保存 | 文件及父目录权限、只读文件系统、POSIX rename 扩展、文件版本是否被其他程序修改 |
| 本地草稿与远端版本冲突 | 先复制保留草稿，再重新载入远端文件比较；不要反复尝试覆盖 |
| 小窗口终端内容显示不全 | 刷新到最新资源；检查页面缩放、全屏切换和系统软键盘；记录窗口尺寸以便复现 |

目标账户需要修改密码或额外验证码时，应先使用管理员支持的本地 SSH 流程处理。工作台支持个人密码及单个隐藏密码提示，不代替账户维护和多因素认证流程。

## 终端感觉慢时

诊断面板中的三项数据有不同含义：

- **网页往返**：浏览器与网页网关的应用消息往返。
- **校园文件通道**：同一条个人 SSH 连接中的低频 SFTP 状态请求采样，不是逐键回显。
- **终端处理排队**：网页把收到的终端数据交给 xterm 处理完成的排队时间，不包含全部浏览器合成与屏幕绘制。

它们不能直接相加作为实测按键延迟。网页处理排队低，也不代表中转公网段没有重传或秒级停顿。

快速输入栏适合先在本地编辑普通单行命令，Enter 再发送到当前终端。退格和光标移动不等待远端回显；执行结果仍受网络影响。Tab 补全、密码提示、Vim 等交互在原终端内操作。

需要进一步定位时，记录同一时区的明确卡顿时刻，并围绕正在使用的连接同步取样：网页往返、应用排队、外层 SSH 的 RTT/RTO、发送队列和重传增量。新建 TCP 连接耗时只说明建连情况，不能独立证明既有 SSH 隧道的停顿原因。

`ss -ti` 的 TCP 信息只覆盖该条 TCP 连接的两端。若 SSH 经过代理，VPS 观测到的可能只是代理出口到 VPS 的一段，需要客户端应用往返才能覆盖完整路径。累计重传应比较相邻样本的增量；RTO 不是实测按键时延。

拆开个人 SSH 连接仍可能共享同一条外层反向 SSH TCP，不能保证消除传输队头阻塞。比较其他出口或中转设备时，先建立独立测试路径，验证目标主机公钥，再安排应用切换。

## 更新应用

1. 记录当前源码版本、配置和静态资源版本，备份当前应用目录及环境文件。
2. 在独立目录安装依赖、构建，并运行检查与隔离测试。目标 SSH 主机公钥和部署环境配置保留在本地管理。
3. 纯前端更新可以替换静态资源后让成员刷新；当前已打开的页面继续使用它已加载的代码。
4. 后端代码或进程环境变更需要重启应用，会结束现有网页 SSH 会话。安排合适的维护时间；长任务由成员在目标服务器用任务管理器保持。
5. 检查本机 API、HTTPS、WebSocket，并用专门的测试账户和文件做功能验收。

HTML 和 API 使用 `no-store`，静态资源通过内容 ETag 重新验证。部署后可比较 HTTPS 返回资源与本地文件的散列，避免仅检查页面 HTTP 200 就认为新版本已经生效。

## 更换反向通道与回退

新设备的隧道应先使用另一个明确授权的回环端口。SSH 服务的 `PermitListen` 与对应公钥的 `permitlisten` 都必须允许该端口，且绑定范围仍为回环地址。

在新端口验证目标 SSH 主机公钥和可达性后，修改应用的 `LAB_SSH_PORT` 并重启应用。先保留旧通道，完成成员实际登录和交互验证后，再决定是否撤掉它。

回退时把 `LAB_SSH_PORT` 恢复为旧端口并重启应用；应用版本更新则恢复备份版本及相应配置。单纯修改 SSH 环境文件但不重启进程，不会使既有进程自动切换。不要让两个设备抢占同一个反向监听端口。

## 公钥与证书维护

目标 SSH 主机公钥变更时，先从可信管理渠道确认原因及新指纹，再更新 `LAB_HOST_KEY_PATH` 指向的文件并重启应用。不要为排障关闭主机公钥校验。

中转设备丢失或密钥需要轮换时，撤销对应 VPS 授权公钥，再部署新的专用密钥。每台设备使用独立公钥和明确的监听端口，有助于撤销单个设备的权限。

HTTPS 证书续期由所选证书管理工具负责；定期检查续期任务结果和 Nginx 是否已加载新证书。

## 默认边界

| 项目 | 默认限制 |
| --- | --- |
| 成功认证会话 | 全站 8 个，每个用户名 2 个 |
| 待认证连接 | 全站 16 个，每 IP 3 个 |
| 认证失败 | 每 IP 及每用户名分别 5 次 / 5 分钟 |
| 未提交认证等待 | 60 秒 |
| SSH 建立等待 | 20 秒 |
| 空闲会话 | 30 分钟 |
| 会话最长时间 | 8 小时 |
| 文件内容 | UTF-8 普通文件，最多 256 KiB |
| 编辑标签 | 最多 12 个 |

目录服务端最多返回 1000 项，网页每个目录最多展示 300 项并标记截断。需要处理更大目录、二进制文件、上传、删除或其他文件操作时，可在具有相应权限的个人终端中完成。应用重启会重置进程内的认证失败计数；它们不是跨进程的集中限流存储。
